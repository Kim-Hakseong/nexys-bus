# 6. 하드웨어 카드

NexysBus는 카드 드라이버를 **프로그램에 넣지 않습니다**. 드라이버가 설치된 PC에서 연결 파일 `driver.json` 하나로 실행 중에 붙습니다. 이 파일이 없으면 하드웨어 기능은 조용히 꺼지고 가상 버스만 보입니다(오류 없음).

## 6.1 연결 파일 driver.json
exe 옆(포터블은 실행한 exe가 있는 폴더) 또는 `%LOCALAPPDATA%\NexysBus\`에 둡니다.
```json
{
  "cardLibrary": "<카드 API DLL 이름>",
  "busLibrary": "<1553 API DLL 이름>",
  "cardPrefix": "<카드 API 함수 접두어>_",
  "busPrefix": "<1553 API 함수 접두어>_",
  "maxCards": 4
}
```
값은 카드 제조사 SDK의 DLL 이름과 함수 접두어입니다(64비트 DLL, `C:\Windows\System32`에 있는 것). 현장 키트의 템플릿을 복사해 쓰면 됩니다.

## 6.2 카드 찾기와 선택
1. 시작 화면 또는 PROJECT의 **SEARCH HARDWARE** → 상태줄 `Hardware search: 1 card(s)`.
2. PROJECT › DEVICE에 `USB 1553 #0 — 모델 · S/N · 2 × 1553 · ch0 single ch1 single` 같은 카드가 나타납니다. 채널 능력 설명도 한 줄 붙습니다.
3. 카드를 눌러 SELECTED → BUS 카드에서 CHANNEL(BC 채널)과 필요하면 MONITOR CH.
4. SIMULATE에서 **START**. 같은 프레임이 실제 버스로 나가고, 캡처 형식·ANALYZE 화면은 가상 버스와 같습니다.

## 6.3 단일 기능 채널과 다중 기능 채널
카드 채널에는 두 종류가 있습니다. NexysBus는 열 때 드라이버에 물어 자동으로 판단하고(`ChannelRoles` 규칙 한 곳), 화면에 표시합니다.

| | 다중 기능(multi-function) | 단일 기능(single-function) |
|---|---|---|
| 한 채널에서 | BC + 시뮬레이트 RT + 모니터 동시 | BC·RT·모니터 중 하나 |
| BC가 보낸 기록 | 채널의 순차 모니터 | **메시지 블록**(메시지마다 마지막 트랜잭션: 타임태그·상태어·데이터)을 5 ms마다 읽어 기록 |
| RT 흉내 | 같은 채널에서 가능 | 불가 — 실제 RT가 대답해야 함(없으면 NO RESPONSE) |
| 전체 버스 모니터 | 같은 채널 | **두 번째 채널을 같은 버스에 연결하고 MONITOR CH로 지정** |

> 단일 기능 채널에서 BC 옆에 RT나 모니터를 억지로 구성하면 드라이버가 거부하면서 BC 스케줄까지 지워 버리는 것이 실측으로 확인됐습니다. NexysBus는 이런 호출을 아예 하지 않습니다.

## 6.5 문제가 생기면
| 증상 | 확인 |
|---|---|
| SEARCH HARDWARE가 회색 | `driver.json`이 exe 옆이나 `%LOCALAPPDATA%\NexysBus\`에 있는지, 키 4개가 다 있는지 |
| `CardOpen(0) = -13` | 카드가 연결·인식되지 않음(장치 관리자 확인) |
| 응답률 0 %, 오류어 `8003`/`8001` | 그 버스(A/B)에 RT가 없음 — 배선과 BUS 열(A/B) 확인. `hw_scan_rt.py`로 RT 0–30을 A/B 양쪽에서 찾아볼 수 있습니다 |
| `n not read`가 큼 | 단일 기능 채널에서 PC가 바빠 메시지 블록을 늦게 읽음 — 다른 무거운 작업을 멈추거나 두 번째 채널 모니터 사용 |
